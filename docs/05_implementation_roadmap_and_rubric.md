## 1. 5-Phase Post-Planning Implementation Roadmap

Once this pre-build Application Plan (`APPLICATION_PLAN.md` and `docs/01..05_*.md`) is reviewed and approved, code implementation proceeds across five incremental, independently verifiable phases:

| Phase | Milestone Name | Target Modules & Deliverables | Independent Verification Gate |
|---|---|---|---|
| **Phase 1** | **Foundation, 8-Table SQLite Schema & Self-Updating Israeli MoE Calendar Engine** | • Initialize `backend/` (`Python 3.13 + FastAPI + Pydantic v2`) & `frontend/` (`React 19 + TS + Vite + Tailwind v4 RTL`).<br>• Execute `schema.sql` (`8` tables in SQLite 3.53 WAL mode, including `passenger_loyalty_wallets`).<br>• Bundle verified MoE JSON calendars (`moe_5786_2025_2026.json` & `moe_5787_2026_2027.json`) + implement **`MoECalendarAutoUpdaterService`** (annual circular sync + `pyluach`/`Hebcal i=on` statutory rule projector for `2027–2028+`).<br>• Implement `MoECalendarService`, `VacationMaximizerEngine`, and **Mode 3 (`HOLIDAY_DIRECT_INTENT`)** holiday-year parser. | `pytest` unit suite verifying:<br>• All 8 `MoEFrameworkType` schedules<br>• Middle School (`7–9`) hybrid rule & June 20 summer start<br>• Annual Auto-Updater projection for `תשפ"ח (2027–2028)` & Mode 3 resolution (*"חופשת פסח בשנת 2027"* $\to$ `Apr 13–28, 2027`)<br>• Nitzanim Hanukkah/Pesach/July windows & `TLV` Yom Kippur shutdown blocker<br>• Exact `PER`, `SAP`, `CCG`, and `VUS` math across Examples 1–6. |
| **Phase 2** | **El Al `rbddataclients` Connector, Multi-Club Per-Passenger Wallets & 6-Strategy Bonus Synthesizer** | • Implement `ElAlRbdDataClientAdapter` (`providers/elal_rbd_client.py`) targeting `https://www.elal.com/rbddataclients/` with metro-to-airport IATA expansion (`NYC`$\to$`JFK`/`EWR`, `LON`$\to$`LHR`/`LTN`), Playwright/XHR interception, token-bucket rate limiter, and 4h SQLite TTL cache.<br>• Implement `MultiClubWalletAllocationEngine` & `BonusVacationPlannerService` solving all **6 Family Bonus Fulfillment Strategies** (including `MULTI_CLUB_PER_PASSENGER_SPLIT` across individual passenger balances and multiple clubs). | Unit & recorded-fixture integration tests verifying:<br>• `0`, `1`, and `2` (`2+` cap) parsing across Economy (`E`/`X`/`U`), Premium (`P`/`A`/`R`), and Business (`I`/`W`)<br>• Per-passenger & multi-club point wallet allocation (`ELAL_MATMID`, `BRITISH_AVIOS`, `FLYING_BLUE`, `UNITED_MILEAGEPLUS`, `MILES_AND_MORE`, `AMEX_MR_ISRAEL`, etc.) without exceeding individual balances<br>• All 6 fulfillment strategies for a 5-person family (`FBVS` & `CTOS`). |
